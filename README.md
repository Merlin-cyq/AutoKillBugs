# AutoKillBugs

星露谷物语 1.6 的 SMAPI 模组：矿井里的**蛆（Grub）**和**苍蝇（Fly）**一出现就自动死亡，但**掉落物、经验值和探险家公会的击杀进度全部照常保留**——因为它走的是游戏自己的击杀流程，而不是「把怪物删掉」。

---

## 这个模组做什么

在矿井、骷髅洞穴、采石场矿井以及突变虫穴里，蛆和苍蝇（含「危险矿井」与「突变虫穴」里的强化变体）一旦加入场景就立刻死亡。

关键在于**死亡方式**：模组调用的是游戏自己在玩家挥武器命中怪物时走的那条路径。因此怪物死亡时的每一个结算环节都会照常发生：

- **掉落物**——按游戏原版掉落表掉落：虫肉、稻苗、白藻、古代种子、矮人卷轴，以及「到过矿井底部后」才会追加的钻石与五彩碎片等
- **经验值**——照常获得
- **探险家公会进度**——「杀死洞穴昆虫」（80 只）照常计数
- **其它原生钩子**——击杀任务、特殊订单、附魔「杀戮」、窃贼戒指……一律照常

## 这个模组不做什么

明确地说，它**不会**：

- ❌ 直接删除怪物对象
- ❌ 只把怪物血量置 0
- ❌ 隐藏怪物贴图
- ❌ 修改刷怪表（它不阻止怪物生成，只是让它们立刻死）
- ❌ 碰你的游戏存档（一行都不写）

前四种做法虽然也能让虫子消失，但全都绕开了游戏的击杀结算，结果是**什么都掉不出来、也不计数**。那正是本模组刻意避开的路子。

## 安装

1. 先装 [SMAPI](https://smapi.io/)（**4.5.2 或更高**）
2. 到本仓库的 Releases 下载 `AutoKillBugs-1.2.0.zip`
3. 解压，把里面的 `AutoKillBugs` 文件夹整个放进游戏的 `Mods` 目录
4. **用 `StardewModdingAPI.exe` 启动游戏**（不要直接点游戏本体）

装好后路径应该长这样：

```
Stardew Valley/Mods/AutoKillBugs/AutoKillBugs.dll
Stardew Valley/Mods/AutoKillBugs/manifest.json
Stardew Valley/Mods/AutoKillBugs/config.json
Stardew Valley/Mods/AutoKillBugs/README.md
```

**卸载**：把 `Mods/AutoKillBugs` 文件夹删掉即可。本模组从不写存档，卸载不会留下任何残留。

## 配置

三个开关，默认全部开启：

| 选项 | 默认 | 说明 |
|---|---|---|
| `Enabled` | `true` | 总开关。关掉后本模组什么都不做（等价于没装） |
| `OnlyInMines` | `true` | 只在矿井 / 骷髅洞穴 / 采石场矿井 / 突变虫穴生效。关掉则对所有地点生效（例如别的模组添加的地下城） |
| `DelayOneFrame` | `true` | 见下方专门说明 |

### 三条改配置的路

1. **游戏内按 `F9`**（推荐）——弹出一个原生风格的设置菜单，点一下开关**立即生效**并写回配置文件。`Esc`、鼠标右键、右上角 ✕、再按一次 `F9` 都可以关；标题界面和游戏内都能打开。
2. **直接编辑** `Mods/AutoKillBugs/config.json`——改完重进游戏生效。
3. **Generic Mod Config Menu**（可选）——如果你装了 [GMCM](https://www.nexusmods.com/stardewvalley/mods/5098)，标题界面的 `Mod Options` 里会自动多出同样三项。没装的话这条静默跳过，不会有任何报错或警告。

F9 是本模组唯一占用的按键；三个开关本身不占任何键位。

### `DelayOneFrame` 到底是什么

这是一个取舍，看你更想要哪一边：

|  | `true`（默认） | `false` |
|---|---|---|
| 虫子会显示吗 | 会闪过大约 1 帧（1/60 秒） | 一帧都看不到 |
| 掉落物 | **完整**（含「到过矿井底部」后追加的钻石 / 五彩碎片等） | 可能缺少那部分追加掉落 |

原因在于：游戏里有一部分额外掉落，是在怪物**第一次执行自己的 update 时**才根据所在矿层的难度算出来的。选 `true` 时模组先把怪物登记下来、下一个游戏帧才动手，保证每只虫都至少跑过一次 update，所以那部分掉落一定拿得到——代价是它会在画面上闪一下。选 `false` 时模组在虫子加入场景的同一帧就把它杀掉，视觉上完全干净，但「在常规更新之后才加入场景」的虫子（典型例子是蛆蛹化后孵化出来的那只苍蝇）从没跑过 update，那部分追加掉落就拿不到。

**两种模式的基础掉落、经验和击杀计数完全一样**，差别只在上表那部分追加掉落。如果你更在意「一眼都不能看见」，把它改成 `false`。

## 它是怎么实现的

给想改代码、或者单纯好奇的人。

### 只用游戏自己的击杀入口

模组唯一使用的击杀手段是：

```
GameLocation.damageMonster(Rectangle, minDamage, maxDamage, isBomb, knockBackModifier,
                           addedPrecision, critChance, critMultiplier,
                           triggerMonsterInvincibleTimer, who, isProjectile)
```

也就是玩家挥动武器或投掷炸弹命中怪物时游戏自己调用的那个方法。它内部在怪物血量归零时会走 `onMonsterKilled`，而掉落、经验、公会计数、任务通知、把怪物移出场景全都在那条链上。

直接 `characters.Remove(...)` 或者只把 `Health` 置 0 都不行：游戏自己的 `updateCharacters` 会在下一帧把血量 ≤ 0 的怪物静默移除，**没有任何结算**。

### 为什么挂在 `UpdateTicked` 上

SMAPI 的 `GameLoop.UpdateTicked` 触发点紧跟在真正的 `Game1.Update`（怪物就是在其中被生成并加入场景的）之后、仍在同一帧的 `Draw` 之前。所以在这个时机击杀，怪物在它出现的那一帧就已经被移出场景，玩家一帧都看不到。

（SMAPI 的 `World.NpcListChanged` 事件天生比这晚一帧，用它的话虫子至少会被绘制一帧，所以没有采用。）

### 音效与特效

蛆和苍蝇死亡时调用的音效**不带位置参数**，游戏对这类音效一律按满音量播放——也就是说，如果不管它，你会听到一串「看不见的东西在死」的声音。

模组的做法是给 `GameLocation.playSound` 装一个 Harmony 前缀补丁，**只在自动击杀那一瞬间**跳过播放。补丁安装失败也不影响击杀与掉落，只会在 SMAPI 控制台记一条警告。

死亡时的伤害数字与动画精灵同样会在这一个窗口内被清掉。

### 蛹化怎么处理

蛆被打到半血会进入「蛹化」——那段时间它免疫一切伤害，随后孵化成一只苍蝇。由于本模组在蛆一出现时就把它处理掉，正常情况下一只蛆永远到不了半血。万一某只蛆已经处于蛹化状态，模组会先解除它的蛹化标志再动手；就算它抢先孵化成功，那只新苍蝇同样在击杀范围内，不会漏。

### 多人游戏

怪物在多人游戏里由主机持有，客机强行修改会让两端不同步。所以模组只在主机端生效，客机端会记一条警告并保持不动。

## 已知边界

- **只处理玩家当前所在地点**。已经离开的矿层里剩下的虫子不会被远程清理，交给游戏自己处理。
- **只在主机端生效**（见上）。
- **`DelayOneFrame = true` 时虫子会闪一帧**。想彻底看不到就把它改成 `false`，代价见上面的对照表。
- **追加掉落有前置条件**。钻石 / 五彩碎片只在「你至少到达过矿井底部一次」之后才可能出现；齐豆与彩蛋还分别需要特殊订单和沙漠节。没满足条件时两种模式的掉落完全一样。
- **没有在真实游戏里跑过完整验证**。这个模组的验证是**静态验证**：编译 0 警告 0 错误、程序集元数据核对、对交付的 dll 独立重编译后逐行比对 IL（差异 0 行）与反编译 C#（差异 0 行）、逐个核对游戏 API 调用点。菜单的实际外观、点击手感这类东西只能靠你自己看。
- **三个已知的低危小瑕疵**（都保留未修，不影响使用）：
  1. 当因为「当前已经开着别的菜单」而没能打开设置菜单时，那一次 `F9` 按键仍会被抑制掉——它不会传给别的模组，也不会触发游戏功能（星露谷默认没给 F9 绑任何功能）。
  2. 菜单绘制时没有同步鼠标的 Y 坐标，某些分辨率下鼠标「是否悬停在菜单上」的判定可能走默认分支（纯视觉细节）。
  3. 关闭菜单时没有自校验子菜单指针是否仍指向自己（静态分析判定该路径不可达）。

## 自己编译

需要 **.NET 6 SDK**。

```bash
git clone <本仓库地址>
cd AutoKillBugs
```

然后编辑 `AutoKillBugs/AutoKillBugs.csproj`，把里面的游戏路径改成你自己的：

```xml
<GamePath>你的星露谷安装目录</GamePath>
```

再编译：

```bash
dotnet build AutoKillBugs/AutoKillBugs.csproj -c Release
```

项目使用了 [Pathoschild.Stardew.ModBuildConfig](https://www.nuget.org/packages/Pathoschild.Stardew.ModBuildConfig) 这个 NuGet 包，它会自动处理对游戏程序集的引用。产物是一个 `net6.0` 的类库——游戏本体自包含 .NET 6 运行时，所以目标框架必须是 `net6.0`。
